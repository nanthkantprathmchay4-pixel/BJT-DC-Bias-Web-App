## 1. สิ่งที่ได้เรียนรู้

- Web Application ที่ใช้งานได้จริงไม่ได้จบที่ไฟล์ HTML แต่ประกอบด้วย
  Template (สิ่งที่ผู้ใช้เห็น) → Flask Route (ตัวรับ request) →
  Engineering Module (ตัวคำนวณ) → Tests (ตัวพิสูจน์ว่าถูก)
- การแยก `dc_bias.py` ออกจาก `app.py` ทำให้ทดสอบสมการได้โดยไม่ต้องเปิดเว็บ
  และเมื่อแก้สมการก็ไม่ต้องแตะ HTML เลย
- ค่าที่ผู้ใช้กรอกเป็น kΩ แต่สมการต้องใช้ Ω ทำให้การแปลงหน่วยเป็นจุดที่ผิดพลาดได้ง่าย
  จึงต้องมี test สำหรับเรื่องนี้โดยเฉพาะ
- การแสดง warning เมื่ออยู่นอก Forward-Active Region สำคัญพอ ๆ กับการคำนวณ
  เพราะตัวเลขที่ออกมาอาจดูปกติแต่ไม่มีความหมาย

## 4. คำถามรายบุคคล

**เหตุใดการเปิด `templates/index.html` ตรง ๆ จึงไม่เท่ากับการรัน Flask?**

เพราะการเปิดด้วย `file://` เป็นการให้เบราว์เซอร์แสดงไฟล์นิ่ง ไม่มีเซิร์ฟเวอร์
ไม่มี route และไม่มีการเรียก Python เลย เมื่อกดปุ่ม Calculate จะไม่มีอะไรคำนวณ
ผลลัพธ์ที่เห็นจึงเป็นเพียงโครง HTML ที่ยังไม่มีข้อมูล

**ฟอร์มส่งข้อมูลไป Python อย่างไร?**

`<form method="post" action="/">` ทำให้เบราว์เซอร์สร้าง HTTP POST ไปที่ path `/`
โดยส่งค่าของ input ทุกช่องที่มี `name` มาใน request body แบบ
`application/x-www-form-urlencoded` Flask จึงอ่านได้ผ่าน `request.form`
แล้วส่งต่อให้ `validate()` และ `calculate()`

**แก้สมการใน `dc_bias.py` แล้วต้องแก้ HTML หรือไม่?**

**ทำไมผลใน Region ที่แบบจำลองใช้ไม่ได้จึงต้องมี Warning?**

เพราะสมการ Forward-Active ตั้งอยู่บนสมมติฐานว่าไดโอดเบส-อีมิเตอร์นำกระแส
และรอยต่อคอลเลกเตอร์-อีมิเตอร์ไม่อิ่มตัว เมื่อวงจรอยู่ใน Cutoff หรือ Saturation
