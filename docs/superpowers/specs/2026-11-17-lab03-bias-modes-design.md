## 6. การออกแบบ

### 6.1 สมการและค่าอ้างอิงอิสระ

ใช้ร่วมกัน: `VCC = 12 V`, `RC = 2.2 kΩ`, `β = 100`, `VBE = 0.70 V`

| โหมด | สมการ IB | อินพุตเพิ่ม |
|---|---|---|
| Fixed | `(VCC − VBE) / RB` | RB |
| Emitter | `(VCC − VBE) / [RB + (β+1)RE]` | RB, RE |
| Divider | `(VTH − VBE) / [RTH + (β+1)RE]` | R1, R2, RE |

ทุกโหมด: `IC = β·IB`, `IE = (β+1)·IB`, `VE = IE·RE` (Fixed: `VE = 0`),
`VB = VE + VBE`, `VC = VCC − IC·RC`, `VCE = VC − VE`

ค่าอ้างอิงที่คำนวณมือ (ใช้ในเทสต์และตาราง A1–A5):

| กรณี | อินพุต | IB | IC | VC | VCE |
|---|---|---|---|---|---|
| A1 Divider | R1=100k, R2=22k, RE=1k | 12.2986 µA | 1.2299 mA | 9.2943 V | 8.0522 V |
| A2 Fixed | RB=1 MΩ | 11.3000 µA | 1.1300 mA | 9.5140 V | 9.5140 V |
| A3 Emitter | RB=1 MΩ, RE=1k | 10.2634 µA | 1.0263 mA | 9.7421 V | 8.7054 V |
| A4 Emitter | RB=1 MΩ, RE=2k | 9.4010 µA | 0.9401 mA | 9.9318 V | 8.0328 V |

A4: เพิ่ม RE → ตัวส่วนมากขึ้น → IB, IC ลดลง และ VCE เพิ่มขึ้น (ทิศทางที่ต้องทำนายก่อนรัน)

### 6.2 `dc_bias.py`

- ค่าคงที่ใหม่: `MODES = ("divider", "fixed", "emitter")`,
  `SATURATION_VCE_LIMIT = 0.2` (เปลี่ยนจาก 0.3 ตามใบงาน)
- `REQUIRED_FIELDS` และ `RESISTOR_FIELDS` แยกตามโหมด
- `BiasResult` เพิ่ม `vth`/`rth` เป็น `float | None = None` เพื่อให้ Fixed/Emitter
  ไม่ต้องใส่ค่าที่ไม่มีความหมาย
- Shared helper คำนวณ `IC, IE, VE, VB, VC, VCE` และตัดสิน region จาก IB
  โดย Divider คงลำดับการคำนวณเดิมไว้เพื่อให้ float ออกมาเท่าเดิม
- `parse_mode(raw)` คืน `(mode, error)`; ค่าที่ไม่รู้จักต้อง error ไม่เดาเป็น Divider
  - ค่า `None`/สตริงว่าง (client รุ่นเก่าและ test เดิมที่ POST ไม่มีช่อง `mode`)
    ถือเป็น `divider` เพื่อคงสัญญาเดิมของ Lab 2
  - ค่าที่ส่งมาแต่ไม่ตรงกับ `MODES` → error
- `validate(form, mode="divider")` ตรวจเฉพาะช่องของโหมด ใช้ข้อความเดิมทุกข้อ:
  - ว่าง → `กรุณากรอกค่านี้`
  - ไม่ใช่ตัวเลข/nan/inf/ล้น → `ต้องเป็นตัวเลข`
  - VCC, RB, R1, R2, RC, RE, β ≤ 0 → ข้อความเดิมของแต่ละช่อง
  - VBE < 0 หรือ ≥ VCC → `VBE ต้องอยู่ระหว่าง 0 ถึง VCC`
  - ช่องของโหมดอื่นถูก **เพิกเฉยทั้งหมด** (A2 ส่ง RE=0 หรือ RE=abc ก็ต้องผ่าน)
- Region:
  - IB ≤ 0 → `cutoff` + warning
  - VCE ≤ 0.2 V → `saturation` + warning (ข้อความใหม่ระบุ 0.2 V)
  - อื่น ๆ → `active`

### 6.3 `app.py`

- `MODE_LABELS` และ `MODE_FIELDS` (ชื่อ, label, หน่วย, ลำดับช่องต่อโหมด)
  เป็นข้อมูลแสดงผล ไม่มีสมการ
- GET: อ่าน `mode` จาก query string (ไม่มี → `divider`); ค่าไม่รู้จัก → แสดง
  error `ไม่รู้จักโหมดวงจรที่เลือก` และไม่แสดงฟอร์มอินพุต/ผลลัพธ์ แต่ยังแสดง
  แถบโหมดเพื่อให้กลับไปโหมดที่ถูกได้
- POST: อ่าน `mode` จาก hidden input; ไม่มี → `divider`; ไม่รู้จัก → แสดง error
  เดียวกันและไม่แสดงฟอร์มอินพุต/ผลลัพธ์
- `if/elif` เรียก `calculate`, `calculate_fixed`, `calculate_emitter`
- ส่ง `fields` (พร้อม value และ error), `mode`, `mode_label`, `steps`,
  `results`, `region`, `warnings` ให้เทมเพลต
- `steps` ต่อโหมด: Divider คง VTH/RTH/IB/IE; Fixed และ Emitter แสดง IB/IC/IE
- เมื่อมี error: `results=None` เสมอกันไม่ให้ผลรอบก่อนปนกับข้อมูลที่ผิด

### 6.4 `templates/index.html` + `static/style.css`

- แถบโหมดเหนือฟอร์ม: ลิงก์ `/?mode=divider|fixed|emitter`
  วางนอก `<form>` (แสดงได้แม้โหมดไม่ถูกต้อง) พร้อม `aria-current="page"`
  ของโหมดที่เลือก
- ฟอร์มมี `<input type="hidden" name="mode" value="{{ mode }}">`
- วน `fields` แสดง label/input/error — ไม่มีเงื่อนไขคำนวณในเทมเพลต
- ผลลัพธ์ขึ้นหัวว่า `ผลลัพธ์ · {{ mode_label }}`
- หมายเหตุท้ายผล: `แบบจำลอง Forward-Active · เกณฑ์เตือน Saturation ที่ VCE ≤ 0.2 V`
- ปุ่ม/label/ช่องมี `for`/`id` ตรงกันเพื่อให้ browser tool หาเจอ
